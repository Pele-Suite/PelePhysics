Transport

PelePhysics supports computation of several transport coefficients: dynamic viscosity (\(\mu\)), bulk viscosity (\(\xi\)), thermal conductivity (\(\lambda\)), mixture-averaged species diffusion coefficients (\(D_i\)), optionally the full multicomponent diffusion matrix (\(\tilde{D}_{ij}\), see Multicomponent diffusion), and Soret coefficients/thermal diffusion ratio (\(\chi_i\)). There are three choices of model for computing these transport coefficients:

  • Constant with user-specified values

  • Sutherland, adding a simple temperature dependence to user-specified values

  • Simple where transport coefficients are computed based on thermochemistry data for the multi-component mixture

The choice between these transport models is made at compile time. When using GNUmake, this is done by setting the Transport_Model parameter in the GNUmakefile.

The appropriate choice of transport model depends on the EOS being used. For perfect gasses (GammaLaw), constant transport must be used. For reacting flow calculations using either the ideal gas (Fuego) or Soave-Redlich-Kwong equations of state, Simple transport is appropriate in most cases. Note that based on code implementation and physics considerations, the EOS/transport combinations of GammaLaw/Sutherland, GammaLaw/Simple, Soave-Redlich-Kwong/Constant and Soave-Redlich-Kwong/Sutherland are not supported and attempting to compile with any of those combinations will lead to an error message similar to this:

error: static_assert failed due to requirement 'is_valid_physics_combination<pele::physics::eos::SRK,
      pele::physics::transport::ConstTransport>::value' "Invalid physics combination attempted"

Note

For the flow solvers in the Pele suite, Soret effects are only supported in PeleLMeX at present. The bulk viscosity is utilized in PeleC but not in the low-Mach algorithm used in PeleLM and PeleLMeX.

Constant

In this model, all transport coefficients are user-specified constants. They can be set in a simulation input file using:

transport.const_viscosity = 1.81e-4
transport.const_bulk_viscosity = 0.0
transport.const_conductivity = 2.623e2
transport.const_diffusivity = 0.242
transport.const_thermal_diffusion_ratio =  0.0
transport.units = CGS

Any unspecified quantity is assumed to be 0.0. The transport.units parameter indicates the units of the parameters set in the input file and can be CGS or MKS. If not specified, CGS units are assumed, and regardless of the value of this parameter the output of all transport functions is in CGS units.

Sutherland

This is another minimal model, based on the temperature dependence of viscosity proposed by Sutherland (1893):

\[\mu = \mu_{ref} \left(\frac{T}{T_{ref}} \right)^{3/2} \frac{T_{ref} + S} {T + S},\]

where \(\mu_{ref}\) is the dynamic viscosity at a reference temperature \(T_{ref}\) and \(S\) is a constant. In the PelePhysics implementation, the thermal conductivity is then computed based on a user-specified Prandtl number, \(\lambda = \mu c_p / Pr\), where the heat capacity \(c_p\) is evaluated using the EOS model. The user may specify constant values for the bulk viscosity and diffusvity (a single value for all species). Soret effects are not supported for this Transport model (\(\chi_i = 0\)).

For Sutherland transport, there are several runtime parameters that may be specified in the input file:

transport.Prandtl_number = 0.7
transport.viscosity_mu_ref = 17.16
transport.viscosity_T_ref = 273.15
transport.viscosity_S = 110.4
transport.const_bulk_viscosity = 0.0
transport.const_diffusivity = 1.0

The values listed above are the defaults for each parameter. Note that the temperature is specified in K and all other dimensional quantities must be specified in CGS units.

Simple

In this model, transport coefficients are evaluated from data available in the chemical mechanisms (set at compilation using Chemistry_Model). The implementation isbased on that in EGlib (see Ern and Giovangigli (1995)) and simplified to compute, by default, only mixture-averaged diffusivities for each species. The full multicomponent diffusion matrix is also available on request (see Multicomponent diffusion). The run-time options are:

transport.use_soret = 0                 # compute Soret coefficients (1) or not (0)
transport.trace_epsilon = 1.e-15        # shift applied to vanishing species, see below
transport.matrix_diffusion_niter = 2    # iterations for the multicomponent diffusion matrix
transport.conductivity_model = mixture  # mixture | lct1 | lct3, see below
transport.conductivity_niter = 3        # conjugate-gradient iterations for lct1/lct3

The values listed are the defaults. These options are read only by the Simple model. The lct1 and lct3 conductivity models are compiled in only with the build option USE_LCT_TRANSPORT = TRUE (GNU make; CMake-based codes define PELE_TRANSPORT_LCT), see Multicomponent thermal conductivity and thermal diffusion ratios; without it, selecting them aborts at initialization.

All Simple transport evaluations start by replacing the mass fractions with “trace” values that are strictly positive but still sum to one,

\[Y_i^{tr} = Y_i + \epsilon \left( \frac{1}{N} \sum_k Y_k - Y_i \right), \qquad \epsilon = \texttt{transport.trace\_epsilon},\]

and deriving the mole fractions from \(Y^{tr}\). This keeps every quantity finite for pure components and vanishing species (as in EGlib) and only affects species whose mole fraction is below roughly \(\epsilon\). The default is the value that was hard-coded before the parameter existed, so the default results are unchanged bitwise; EGlib’s own examples use \(10^{-16}\).

The mixture-averaged diffusivity returned in Ddiag is \(\rho \, (W_i / \overline{W}) \, D_i^{mix}\) with \(D_i^{mix} = (1 - Y_i) / \sum_{j \neq i} X_j / \mathcal{D}_{ij}\) the Hirschfelder-Curtiss approximation, so that the species mass flux is \(\mathbf{F}_i = -\texttt{Ddiag}_i \nabla X_i\).

When Simple transport is used with the Soave-Redlich-Kwong equation of state, additional corrections are used to modify the transport coefficients to account for real gas effects based on Chung et al. (1988). Soret effects are not supported for SRK.

Multicomponent diffusion

In addition to the mixture-averaged diffusivities, the Simple model can return the full multicomponent flux diffusion matrix

\[\texttt{Dmat}_{ij} = \rho \, \tilde{D}_{ij} = \rho \, Y_i \, D_{ij},\]

where \(D_{ij}\) is the symmetric multicomponent diffusion matrix of Ern and Giovangigli, such that the species mass fluxes are

\[\mathbf{F}_i = - \sum_j \texttt{Dmat}_{ij} \nabla X_j .\]

The matrix is stored row-major, Dmat[i*NUM_SPECIES + j], in CGS units (g/cm/s), is independent of pressure (like Ddiag), and satisfies \(\sum_i \texttt{Dmat}_{ij} = 0\) exactly so that the fluxes sum to zero.

The algorithm follows EGlib’s EGSDR1: the Stefan-Maxwell matrix \(L_{[00]}\) is built from the trace-adjusted mole fractions and the binary diffusion coefficients, a projected standard iteration is applied with the splitting that makes the first iterate the Hirschfelder-Curtiss approximation (Ern and Giovangigli (1995)), the iterate is scaled by \(\rho Y_i\) and finally projected, \(\tilde{D} \leftarrow P \tilde{D} P\) with \(P = I - Y \otimes u / \sum_k Y_k\), which enforces mass conservation. The number of iterations is transport.matrix_diffusion_niter (default 2, the EGlib choice; 1 gives the projected mixture-averaged matrix; larger values converge to the exact matrix at a cost of one \(N^3\) matrix product per additional iteration). The matrix_diffusion_niter = 1 diagonal coincides with Ddiag before projection, so the two formulations are consistent. At the default of 2 iterations the matrix differs from the converged solution by 1 to 4 % (relative Frobenius norm, hydrogen and methane mechanisms over flame compositions at 300 to 2500 K); 5 iterations bring this below 0.1 %. The converged matrix agrees with Cantera’s multicomponent coefficients to about 0.1 %.

The matrix is only computed when requested through the extended entry points described in Extended transport API. The Constant and Sutherland models return the projected uniform-diffusivity matrix through the same entry points (which yields the same fluxes as their diagonal coefficients), and Manifold transport aborts. When Simple transport is used with the SRK equation of state, the matrix is built from the density-corrected binary coefficients.

Note

Each matrix evaluation holds \(\mathcal{O}(N^2)\) doubles per thread (about 12 KB for 21 species, 63 KB for 53 species), which is acceptable on GPUs for small to moderate mechanisms (roughly \(N \lesssim 30\)) but reserves a large amount of local memory for larger ones. The flow solvers in the Pele suite do not yet use the multicomponent matrix; the low-Mach diffusion algorithm in PeleLMeX in particular assumes a diagonal Ddiag and would require additional algorithm development.

The TranEval test (Testing/Exec/TranEval, input inputs.2d_Simple_Matrix) exercises the matrix path and checks mass conservation, symmetry of \(\tilde{D}_{ij}/Y_i\), the exact binary-mixture result, and the error with respect to a direct dense solution of the transport linear system.

Multicomponent thermal conductivity and thermal diffusion ratios

By default the thermal conductivity of the Simple model is the empirical mixture rule \(\lambda = (\sum_i X_i \lambda_i^{1/4})^4\) built from the pure-species fits of the mechanism. Setting transport.conductivity_model selects instead a solution of the Ern-Giovangigli transport linear systems, as in EGlib’s EGSLCT1 and EGSLCT3:

  • lct1: the reduced system \(\Lambda_{[e]}\) with one combined (translational + internal) energy mode per species (\(N\) unknowns);

  • lct3: the full system \(\Lambda\) with separate translational and internal energy modes per species (\(2N\) unknowns).

Both are solved with transport.conductivity_niter preconditioned conjugate-gradient iterations (default 3, the EGlib choice; the iterates increase monotonically to the exact solution, which TranEval reaches to round-off with 30 iterations). The systems need the pure-species viscosities, the binary diffusion coefficients, the internal heat capacities, the rotational relaxation numbers (with Parker’s temperature correction) and the collision-integral ratios \(A^*_{ij}, B^*_{ij}, C^*_{ij}\). The latter are the universal CHEMKIN/EGlib polynomial fits in \(\ln(T/\epsilon_{ij})\), with \(\epsilon_{ij}\) built at initialization from the Lennard-Jones parameters, dipole moments and polarizabilities already present in the mechanism (EGlib’s polar/non-polar correction), so no new mechanism data is required.

This is a model choice: when an LCT model is selected, the conductivity returned by all entry points, including the historical ones used by PeleC and PeleLMeX, is the LCT value. The default mixture reproduces the previous results bitwise.

Warning

The LCT conductivity is a different model from the mixture rule, not a refinement of it. Over flame compositions at 300 to 2500 K, \(\lambda_{LCT} / \lambda_{mixture}\) spans 0.82 to 1.05 for the LiDryer hydrogen mechanism and 0.75 to 1.07 for drm19, and is 0.81 for pure H2O at 300 K. Cantera’s multicomponent conductivity agrees with the LCT values to 2 to 3 % and differs from its own mixture rule by the same 15 to 20 %. A flow solver that selects lct1 or lct3 in order to obtain \(\tilde{\chi}\) therefore also changes the heat conduction everywhere, including at isothermal walls.

The LCT models are compiled in only with USE_LCT_TRANSPORT = TRUE (GNU make, through Source/Transport/Make.package) or the preprocessor definition PELE_TRANSPORT_LCT (CMake); see the note at the end of this section for the reason. The models use Parker’s rotational relaxation correction with its standard coefficients (as in EGlib and the CEPTR fits); the bulk viscosity of the Simple model keeps its historical expression for backward compatibility.

The LCT solution also yields the rescaled thermal diffusion ratios \(\tilde{\chi}_i\), available only through the extended entry points (requesting them with the mixture model aborts). The thermal diffusion ratios are \(\chi_i = X_i \tilde{\chi}_i\), they sum to zero, and together with the multicomponent diffusion matrix the Soret contribution to the species mass fluxes is

\[\mathbf{F}_i^{T} = - \sum_j \texttt{Dmat}_{ij} \, \chi_j \, \frac{\nabla T}{T}.\]

Warning

\(\tilde{\chi}\) follows the EGlib/Ern-Giovangigli sign convention of the flux above (light species have \(\chi_i < 0\) and drift towards hot regions). The mixture-averaged Soret coefficients chi produced with transport.use_soret follow the CHEMKIN convention and have the opposite sign for the same physical effect; the two must not be mixed without accounting for this. The magnitudes differ as well: the CHEMKIN fit is a dilute-limit approximation for the light species, and in flame mixtures it exceeds \(X_i \tilde{\chi}_i\) by a factor of 1.5 to 2 for H2 (TranEval reports the ratio when both are computed).

For a pure species the LCT conductivity agrees with the mechanism’s pure-species fit (CHEMKIN’s modified Eucken formula) to about 1 % for non-polar species; for polar species (e.g. H2O) the two models treat the internal-energy self-diffusion differently and differ by up to about 20 % at low temperature.

The conductivity converges quickly (the default 3 iterations are within \(4 \times 10^{-8}\) of the converged value), but \(\tilde{\chi}\) is built from the solution vector itself and converges more slowly: at 3 iterations \(X_i \tilde{\chi}_i\) is within about 10 % of the converged value (1 to 5 % in the median), and the converged values agree with Cantera’s thermal diffusion coefficients to 5 to 7 %. Use transport.conductivity_niter = 10 or more when the Soret fluxes matter.

With the SRK equation of state the LCT systems are built from the dilute-gas binary coefficients and the Chung real-gas correction is applied to the resulting conductivity, as for the mixture rule. The Constant, Sutherland and Manifold models do not provide \(\tilde{\chi}\) and abort if it is requested. Requesting \(\tilde{\chi}\) from the Simple model with the mixture conductivity is a caller error: the model is a run-time option, so check conductivity_model in the transport parameters at setup; it is trapped in DEBUG builds and otherwise returns \(\tilde{\chi} = 0\).

Note

The LCT systems are solved matrix-free, so the only \(N^2\) storage is the packed array of binary coefficients (\(N(N+1)/2\) doubles), plus about \(17 N\) doubles of conjugate-gradient work space: 4.7 KB for 21 species and 18 KB for 53 in total. Because the model is a run-time switch, this storage is part of the local-memory footprint of every GPU kernel that evaluates transport once the code is compiled in, even with the default mixture model: for a 53-species mechanism the stack frame of PeleC’s transport-coefficient kernel grows from 4 KB to 25 KB per thread. This is why the LCT code is opt-in (USE_LCT_TRANSPORT = TRUE / -DPELE_TRANSPORT_LCT); without it an LCT model is rejected at initialization and nothing else changes.

The TranEval test (input inputs.2d_Simple_LCT) checks the antisymmetry of \(\chi\), the error with respect to a direct dense solution, the monotonicity of the iterates, the pure-species closed form of each model, and the agreement of the pure-species limit with the mechanism’s conductivity fits.

Extended transport API

The historical entry points transport(wtr_get_xi, ..., mu, xi, lam, tparm) and get_transport_coeffs(bx, Y_in, T_in, Rho_in, D_out, chi_out, mu_out, xi_out, lam_out, tparm) are unchanged. The additional quantities are obtained through a request/output pair of structs (Source/Transport/TransportTypes.H):

pele::physics::transport::TransportRequest req;   // bools: xi, mu, lam, Ddiag, chi, Dmat, chit
pele::physics::transport::TransportOutputs out;   // pointers: mu, xi, lam, Ddiag, chi, Dmat, chit
req.lam = true; req.Dmat = true; req.chit = true;
out.lam = &lam; out.Dmat = Dmat; out.chit = chit;  // Dmat: NUM_SPECIES*NUM_SPECIES, chit: NUM_SPECIES
trans.transport(req, T, rho, Y, out, tparm);
trans.get_transport_coeffs(bx, req, Y_in, T_in, Rho_in, D_out, chi_out, Dmat_out, chit_out,
                           mu_out, xi_out, lam_out, tparm);

Only the requested quantities are evaluated and only the requested, non-null outputs are written (unrequested outputs, scalars included, are left untouched); Array4 outputs that are not requested may be any array. chi is accumulated into and must be zeroed by the caller. Downstream codes can test for this API with the preprocessor symbol PELE_PHYSICS_TRANSPORT_EXTENDED_API (defined in TransportTypes.H) and for the LCT models with PELE_TRANSPORT_LCT. Dmat_out needs NUM_SPECIES*NUM_SPECIES components (component i*NUM_SPECIES + j holds \(\rho \tilde{D}_{ij}\)) and chit_out NUM_SPECIES components.
